# 阶段交接与简短收尾

已授权、目标明确的小任务由总经理在同一轮完成选题和转派；已有 PM 可用时直接发送一份委托。只有跨项目冲突、缺少必要决定或用户要求暂停才拆出等待轮，不额外安排“方案完成后再授权实施”。每个项目仍由 PM 决定 direct/native/LangGraph 和 0–3 位工程师。

## 使用完成事实

`continue --project <配置> --run <运行> --output <新的绝对路径.json>` 在完成时写出工具生成的 `delivery`，其中包含验收、产物和知识回执引用。直接保存这份结果用于汇报和下阶段接续，不再手写内容相同的交付报告。已完成运行可用 `delivery --project <配置> --run <运行> [--output <新路径>]` 读取，不会重跑验收或知识捕获。未完成、暂停或证据变化时不能生成“已完成交接”。

总经理读取结果摘要；代码所有者负责一次正式验收。除非出现新的失败或证据变化，不因汇报再查一遍相同状态、运行同一验收或生成多份格式相近的清单。

## 控制新阶段输入

交接只包含：本阶段目标、明确配置、上一阶段 delivery 路径、必要的代码入口、未决限制和这次允许的动作。优先控制在约 2,000 中文字符内；复杂必要约束按需引用，不截掉权限、失败状态或验收边界。检索正文按任务限定相关 ID 和预算；不把聊天记录、完整源码或所有知识笔记复制进委托。

短交接不会清除已有任务历史，RAG 也不会。如果成本证据表明旧角色的重复上下文明显，且用户已授权新任务，可在同一 Codex 项目内启用新的阶段角色任务。保留旧任务及旧配置，不归档或覆盖失败记录。模型/推理档位沿用用户指定值；新任务先核对实际身份和新配置，再执行。

`projectIdentity` 包含 PM ID：切换时保存新的阶段配置文件并让登记表指向它，旧配置继续用于历史运行。保留同一个 controlRoot 和工作目录，使旧文件锁仍然有效；不新建控制库绕过 BLOCKED、FAILED 或写集冲突。新阶段合同使用新 runId，不重开上个已完成合同。侧栏角色新建/切换属于用户已授权范围内的显式动作，不能暗中修改 Codex 状态库或伪造原任务 compact。

一次阶段角色建立和配置交接属于设置成本，应与后续产品开发分账；新阶段任务只有正式目标，不另外跑“已读、待命、确认开始”的模型轮次。若配置需在创建回执返回后绑定，可在首个工具调用中有界等待绑定文件，配置未就绪则明确结束等待，不开始未绑定工作。

## 跨项目统一放行

总协调者冻结 portfolio manifest（项目、run、PM、配置身份）；各 PM 预检通过后，在同一轮执行 `start --project <project> --run <runId> --barrier <manifest.json>`。控制器登记 ready 后有界等待；总协调者核对全部预检与冻结合同后调用 `release-portfolio --barrier <manifest.json>` 一次。等待中的进程只能接续读取，不能再次 start；过期、身份变化或部分未就绪均不派工。此机制只同步派工窗口，实际并发人数仍须根据真实任务时间统计。


隔离对照须先实测当前全部执行工具不能跨组读取，并核对可绕过沙箱的入口；未通过则只做功能诊断，不报告效率排名。保留失败与污染记录，新验证不得继承其他组实现或旧测试任务上下文。
