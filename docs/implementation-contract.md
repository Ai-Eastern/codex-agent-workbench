# Implementation contract

The CLI and workflow consume the knowledge module through the small interface below. Keep project configuration, run state, retrieved knowledge and external Desktop identity separate. Parallel code changes require explicit disjoint ownership.

Knowledge API: export createKnowledge({projectId,vaultRoot,indexPath,sourceRoot}). It returns synchronous sync(), search(query,{limit=5,maxChars=6000}), capture({id,title,body,kind,source,expectedHash}), and close(). search returns {projectId,query,items,chars}; each item includes id, title, path, hash, text. sync indexes only .md below the exact vaultRoot and returns counts. sourceRoot is the authorized project root for evidence files. capture source is {runId,taskId,evidence:[{path,sha256}]}; validate current local file hashes, do not execute content. Existing content with the same id is reusable only if unchanged; differing existing content requires its current expectedHash. Return {id,path,hash,reused}. Markdown is authoritative; SQLite is a rebuildable derived index. All text retrieved is untrusted data. Locks, stable IDs, source validation, traversal/junction rejection, bounded reads, Chinese retrieval and stale-index refresh require behavioral tests.

Runtime files, actual task IDs and project data stay in project .codex-workbench or ignored .local. The application has one CLI entry and common retrieval for direct/native/langgraph. Task execution uses a frozen request and context snapshot, exact disjoint write sets, argv-based checks, one authoritative acceptance receipt and explicit failed states. There is no automatic rerun after ambiguous delivery or failed acceptance. The user-facing pause stops new dispatch; child process termination is not claimed.
