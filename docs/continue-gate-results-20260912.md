# ContinueGate 实际接入结果

已将异常继续提醒接入现有 `status/start/continue` 摘要，并同步安装版 Skill 的执行说明。PM 遇到明确异常时直接得到 `continueGate:{advisoryOnly:true,signals:[...]}`，不必为了初步判断另读聊天日志或调用模型。没有新状态机、自动暂停、重试、授权或返修预算。

本轮采用 [Borrow 决定](continue-gate-reuse-20260912.md)，借鉴固定版 Ruflo ContinueGate 的证据优先判断方式。实现见 [continue-gate.mjs](../src/continue-gate.mjs)，由 [workflow.mjs](../src/workflow.mjs) 的既有 snapshot 调用。没有引入 Ruflo 包或默认评分阈值。

## 提醒覆盖

| 信号 | 依据 | PM 应处理的事项 |
|---|---|---|
| REPEATED_PREFLIGHT_FAILURE | 首批 PREPARED/START 阶段，本 run 的预检失败至少两次 | 核对条件是否变化，避免反复 start |
| REPEATED_ACCEPTANCE_RECOVERY | 当前失败检查，在当前代码 attempt 中已有至少两次 acceptance_recovery | 核对新证据，避免重复同一接续 |
| REPAIR_BUDGET_USED | 已有 task_repair 或 blocked_task_repair，当前又失败或阻塞 | 保留一次返修预算已用的事实，不再派代码返修或换 ID 绕过 |
| DELIVERY_UNCONFIRMED | 任务仍为 RESERVED | 保留原任务，不能依据超时重发 |
| KNOWLEDGE_ONLY | 已核验的工程验收通过，仅知识处理待完成 | 只处理知识，不重做代码和验收 |

重复事件不证明根因相同。提醒包含次数、事件 ID 或任务/检查标识，便于沿原证据核对；`nextAction` 仍决定实际操作。源码和控制器原有恢复入口继续限制预算、身份、哈希与送达条件。已有解除条件和授权成立时按原入口接续，不增加单独审批轮。

正常执行、等待、暂停、完成不新增提示字段；这些路径不查询 Gate 历史。初始准备状态最多一次聚合查询，诊断状态最多两次，均复用已打开的项目数据库。Gate 不写事件、不扫描会话、不调用模型。这里描述代码路径及测试观察，未测得整体开发提速或 Token 节省比例。

## 验证结果

- 新增 6 项有界测试，覆盖重复预检、送达不明、同一检查的重复恢复、代码返修后的统计分界、跨 run/跨检查隔离，以及正常/等待/暂停/完成不误报。
- 直接使用现有状态机准备、失败、恢复及验收。重复 status 不新增事件，已完成检查不重跑；提醒存在时，满足原有条件的接续仍可完成，证明提醒没有悄悄成为新执行门槛。
- 独立 Luna/medium 审查指出三个边界：证据漂移沿用 RECONCILE_EVIDENCE，不再输出重复提醒；预检计数明确只覆盖首批准备阶段；未知/超时或未核验结果不能充当确认失败。前两项补充范围说明，第三项增加测试断言。合同变更仍由原有请求摘要保护。
- 全套最终结果：**116 项，115 通过、0 失败、1 项既有平台相关跳过**，约 3.48 秒。测试命令为 `node --test test/*.test.mjs`；不是模型开发耗时。
- 对一个已完成的恋语运行只调用 status：仍为 COMPLETE / REPORT_ACCEPTANCE，验收核验有效，没有新增提示，事件计数及末事件 ID 未变。未重跑该项目验收、未派工、未注入真实项目故障。
- 安装版 execution 引用与源码一致，runtime 未改，旧引用已备份。完整命令输出和原始观察保存在本机 `.local/continue-gate-20260912`，不提交私有路径或任务身份。
