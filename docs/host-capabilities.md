## 基线适配器的可复用行为与缺口

[src/desktop.mjs](../src/desktop.mjs) 是版本敏感的内部 Desktop 桥接，不是稳定公共 API。当前只允许 `read_thread` 和 `send_message_to_thread`，目标限于配置中的 PM/工程师，且固定使用 `hostId: local`。它不能直接代表远程、云端或刚创建的其他工作区已经受到支持。

已有防线应保留：

- 核对真实调用任务与当前管道，发送时重新检查身份；拒绝向自己发送或向未登记目标发送。
- 只读查询状态库，确认任务存在、目录相符且明确未归档；读取宿主结果后再次核对身份与目录。Windows 扩展路径前缀有归一化处理。
- 实际发送前的失败标为 `NOT_SENT`；发送后超时、关闭、畸形/拒绝回执标为 `UNCONFIRMED_DO_NOT_RETRY`，保留对账而非自动重发。
- 错误信息有脱敏和长度限制；帧大小及等待时间有界。
- `send` 原样传递 `cfg.model` / `cfg.thinking`，没有在桥接层静默换成另一个配置。

基线曾在 [contracts.mjs 的 configFrom](../src/contracts.mjs) 中把历史实测组合写成运行白名单，拒绝明确要求的 `gpt-6-astra/ultra`。当前实现已解除这一错误绑定：旧配置保留兼容，新计划配置要求显式模型与推理档位，值通过语法校验后原样传递；支持性仍交由宿主决定。相关回归验证配置和任务包透传，不证明服务实际使用了该模型。Desktop 适配器另增加受限的只读源负责人查询，用于交接核对，不扩大发送目标。

## 后续真实验收入口

控制器合同、计划、路由、资源和 A/B/C 夹具可以继续实现。要把独立项目宿主状态从“未验证”提升为“本轮实测”，还需具备下列具体证据：

1. 用户明确要求创建所需独立项目任务，或提供手动创建后的可绑定任务；按宿主规则取得真实身份与最终工作目录。两种路径分别记状态。
2. 在同一总调度入口绑定 A/B/C 三个项目，核对目录、基线、计划版本、明确模型及真实发送/等待/读取回执；不得以此次单仓库原生审计委派替代。
3. 运行 A 的局部需求变更、B 的中断与真实新上下文接续、C 的资源调整、项目暂停与全局暂停；只有终止证据齐备才记录在途执行者已停止。
4. 保存全角色用量、失败尝试、未观测字段和最终代码证据；真实身份及私有映射仅留本机，公开材料使用代号。没有预算的批量模型比较保持未执行。

在上述证据不足时，WB-00 可交付本报告和可复用代码核验，但不得把 M0 的所有宿主验收或 WB-08 三项目真实验收标为完成。
