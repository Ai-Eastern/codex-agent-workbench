# SmartRetrieval 最小适配：保留原 BM25

本轮完成代码适配与一次同库对照，**增强检索未达到采用标准**。正式默认仍是 BM25；`smart` 保留为显式实验入口，未用于恋语下一项真实开发，没有新增桌面角色或产品派工。这个结果只适用于本次本地中文适配及小型知识库，不能推广为 Ruflo 整体无效。

## 已完成的实现

复用 Ruflo 的 RRF 排名融合与 MMR 选择方式，沿用 Workbench 的中文词项、项目身份、来源哈希与 Markdown 权威知识源。原查询和多字符词项变体在同一次索引同步后执行；使用最多 50 个候选，归一化相关性后按固定 0.8 权重平衡相关性与多样性，最后统一限制输出长度。没有新增依赖、模型调用、向量服务或 AgentDB。

默认 `search` 行为不变；CLI 可显式使用 `--strategy smart`，新任务可设置 `knowledge.strategy:"smart"`，旧冻结任务包保持不变。已安装 Skill 的知识参考同步了该入口及其证据限制。源码与许可见 [复用决定](smart-retrieval-reuse-20260912.md) 和 [第三方声明](../third_party/README.md)。

## 同库观察结果

冻结恋语项目的 13 篇 Markdown，共 23,207 字节。独立 Luna/medium 子 Agent 制定 18 个问题，其中 15 个可回答、3 个无答案。算法和参数在维护者查看题目之前冻结；标签尚未经人工校准。

两种检索使用同一知识快照、同一来源验证、最多 5 篇、正文最多 1,800 字符。各做一次空查询预热，随后每题每策略执行一次并交替先后顺序；共 36 次计时检索。来源、快照、算法、标签及评测脚本哈希在执行中核对。计时包含搜索自身的知识扫描/来源校验，排除评测器额外的指纹核对和评分；这是不同查询的单次配对观察，不是重复运行的性能基准。

| 指标 | 原 BM25 | 本地 smart 适配 |
|---|---:|---:|
| 可回答题必需证据覆盖 | 15/15 | 14/15 |
| 首个有效证据的平均倒数排名（MRR） | 0.9667 | 0.9333 |
| 无关或未包含所需引文的返回条目 | 60 | 61 |
| 3 道无答案题的返回条目 | 12 | 12 |
| 18 题累计正文字符 | 32,253 | 32,226 |
| 检索耗时中位数 | 23.39 ms | 25.98 ms |

证据覆盖要求引文实际进入返回正文，仅返回笔记 ID 不算命中。无答案题的返回条目用于观察干扰内容，不代表模型已生成错误答案；本轮没有进行回答生成或幻觉率测试。字符不是 token，27 字符的差异不能当作费用节省。

## 退化发生在哪里

case-14 查询一个精确函数的返回契约。原检索把必需笔记排在第 2 位，完整返回 506 字符；增强检索把它放到第 5 位，前面的材料已占用大部分预算，最终仅剩 62 字符，回答所需的契约内容被截掉。

因此，虽然笔记仍在 Top-5，实际提供给模型的证据已经丢失。本次融合与多样性重排没有保护好精确契约问题的必要材料；未再做消融或调参，不能把全部变化单独归因于 RRF 或 MMR。

预先确定的采用条件是：每题必需证据覆盖不低于基线、无答案干扰和无关条目不增加，并至少改善一项有效指标。本轮三项条件均未通过，故保留原策略，并停止本轮增强版的产品接入。

## 校验与输入修正

- 框架测试 110 项：109 通过，1 项 Windows 符号链接环境跳过，0 失败。针对性检查实际计数了扫描次数，验证一次同步、多查询、中文去重、项目/ID 范围、失效来源排除和冻结包复用。
- 评测脚本经自造普通笔记与带来源回执的笔记检查；再次运行时会在搜索前拒绝覆盖已有结果。
- 首次真实命令在标签校验阶段失败，未创建知识实例、未执行排名：若干中文文件名的笔记仍保留 capture 元数据 ID，独立标注却按普通文件名计算了 ID。
- 保留原始标签及失败记录后，仅将 10 个标签引用映射到原笔记的稳定 ID；问题、引文、必需性、答案分类与采用标准均未改变。随后完成一次有效对照，无结果后调参或反复重跑。
