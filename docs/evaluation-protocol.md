# 评测协议

**状态：待实施的公开评测设计，不是已完成的 benchmark。** 本页不提供成功率或提速结论。历史单功能试验保留在 [三组功能协议](comparison-protocol.md) 和 [执行结果](comparison-results.md)；不把历史观察拼接为新样本。

## 三层证据分别报告

| 层级 | 方法 | 可以证明 | 不能据此证明 |
| --- | --- | --- | --- |
| 机制验证（conformance） | 合成输入、确定性执行器、受控故障注入 | 重复调用、文件归属、失败保留、恢复和证据校验符合合同 | 模型编码能力、生产可靠性、真实提速 |
| 真实模型编码评测 | 冻结任务、起始仓库、执行配置和独立验收，逐次运行模型 | 指定样本与配置下的合格交付率、时间和用量 | 任意仓库上的普遍优势、真实用户满意度 |
| 人工／用户验证 | 人工审查差异，执行真实界面或使用流程 | 被实际检查的可用性、需求符合度和审查结论 | 未检查设备、服务、团队或生产环境的效果 |

报告中每条结果都必须标明证据层级。机制演示不得显示为“AI 完成率”，命令验收不得自动将 `humanVerified` 设为真。

## 真实模型评测的冻结清单

计划使用两个可公开、无敏感数据的样例仓库，共 **60 项任务：24 项缺陷修复、24 项小功能、12 项局部重构**。每题每种方案运行 **3 次**；每种方案固定 180 次，两种方案比较即 360 次。仓库、任务与类别分配必须在首次评分运行前发布；不足 60 项时按实际规模报告，不能仍标成完整集。

在有版本的评测 manifest 中冻结以下内容并记录 SHA-256：

- 两个仓库的来源、许可、基线 commit、依赖锁文件、环境镜像或运行时版本。
- 任务 ID、类别、完整提示、可见测试、允许读取的知识范围，以及独立验收包版本。隐藏包先公布摘要承诺值，评测结束后提供可复核材料；无法公开部分明确限制。
- 每种方案的控制器、Skill 和执行器 commit；模型请求标识、推理设置、工具权限、最大并行数和上下文策略。服务端实际返回的模型标识单列；拿不到就写未知，不能用请求值证明运行身份。
- 相同的任务级 **60 分钟**总时限、模型/工具调用预算及用量预算。确切数值在开跑前固定；不得按初步成绩为某个方案加预算。
- 运行顺序与随机种子：按任务和重复次数分块，平衡方案先后顺序。每次使用干净状态与独立知识副本，不把先前任务答案、隐藏测试或对照方案轨迹传给后续运行。

基线建议采用同模型、同工具和知识输入的单 Agent；实验方案使用 Workbench。不同模型或额外知识属于独立实验条件，不得将其收益全部归因于编排。只固定请求模型但无法核对实际模型时，结果需保留这一限制。

## 独立验收与一次最终提交

隐藏验收由独立维护者在实现运行前编写并冻结。生成 Agent 无权读取、修改或调用隐藏验收包；使用独立评测进程/身份或容器，只接收最终补丁、公开合同和冻结基线。仅把文件放到另一目录、在提示词中禁止读取、设置 Git worktree，都不足以证明隐藏隔离。

先以合成标记验证文件、任务历史、工具与委派通道不能泄漏答案；发生可达路径时停止该批盲测并记录污染。当前 Desktop 历史实验存在隔离反例，不能直接作为已通过的隐藏验收环境。

每次运行允许在预算内使用可见测试并修正代码，但只提交一次最终补丁。独立验收组合公开回归、隐藏断言、适用的类型检查和静态约束，检查本身不得修改提交产物。不把隐藏失败反馈给 Agent 后继续计为同一次通过；需要研究返修时建立另一个预注册实验。

最终提交后冻结补丁/commit、产物清单和验收输入哈希。人工代码审查、GUI 检查与合并决定另存记录，不改变已经发布的机器验收分数。

## 失败、时间和成本口径

- **计时起点**：冻结任务合同交给执行器并可开始执行。**终点**：独立验收生成最终机器结论。使用单调时钟计算耗时，UTC 时间戳辅助审计；模型等待、工具执行、调度、重试和验收全部在内。环境预热/资源准备另计并报告。
- **主成功率**：在 60 分钟总时限和预算内，唯一最终提交通过全部机器验收的次数 ÷ 该方案预定 180 次。中断、超时、超预算、缺失提交、污染或不完整记录不计成功；保留状态和原因。分别报告各类别及每次重复的结果，不取三次中的最好一次。
- **主耗时**：成功样本使用到验收结论的实际秒数；失败、缺失或超时样本统一记 3,600 秒，计算全部预定运行的中位数，明确标为“失败封顶计时”。同时报告实际观测耗时、超时数和成功样本条件中位数；后者不能代替主耗时。
- **基础设施故障**：原记录保留在主表。只有预注册的外部故障条件才允许补跑，补跑另设 `replacementOf`，单列敏感性分析；不删除原失败，不事后挑选更优结果。
- **用量与费用**：汇总执行者、PM、工具侧模型调用及失败尝试。缓存输入属于输入，推理输出属于输出，均不重复相加；缺失计数写 `null`。计数与账单分别记录，订阅额度、文本字符数不能替代真实 Token 或费用。

方案差异按同任务配对展示，置信区间以任务为重采样单位，避免将同一题的三次结果当作完全独立样本。发布原始分子、分母和分布；样本不足或控制条件偏离时限制结论。

## 20 项故障集单独计分

故障集用于机制验证，与 180 次真实编码评测分开。先冻结 20 项清单，可按身份/重复、派送不确定、验收中断、文件/来源漂移四类各 5 项组织。每项必须写明注入位置、预期拒绝或恢复状态、禁止发生的副作用、执行次数与可核查证据。

预期拒绝成功属于机制通过，不属于编码任务交付成功。恢复演示需同时验证原失败仍在、已通过检查不重跑、重入不重复派工、完成项不被重写。现有 [恢复测试](../test/recovery.test.mjs)、[派送测试](../test/dispatch-recovery.test.mjs)、[提交测试](../test/submit.test.mjs) 和 [知识测试](../test/knowledge.test.mjs) 可复用，但测试用例数量不能直接充当“20 项故障实验已完成”。

## 原始记录约定

每次运行写一条 JSONL 元数据，使用合成 ID 和仓库内相对路径。下列字段是待实现的记录合同；未观测值为 `null`，不可填造。

  "protocolHash": "sha256:<manifest>",

  "taskId": "task-001",
  "repositoryId": "fixture-a",
  "category": "bugfix",
  "variant": "baseline",
  "repetition": 1,
  "replacementOf": null,
  "baselineCommit": "<commit>",
  "controllerCommit": "<commit>",

  "hiddenChecksHash": "sha256:<hidden-checks>",
  "environmentHash": "sha256:<environment>",
  "model": { "requested": "<frozen-model>", "observed": null, "settingsHash": "sha256:<settings>" },
  "budget": { "wallSeconds": 3600, "modelCalls": null, "toolCalls": null, "totalTokens": null },

示例预算中的 `null` 仅表示设计尚未填齐，正式 manifest 不得含未确定的预算。过程事件至少记录顺序号、时间、run/task/attempt、派送意图及应答、结果提交、验收、故障与恢复；保存每次尝试，不用最后一条成功覆盖历史。原始日志可按授权留存，公开副本需脱敏并保留摘要；脱敏摘要不是不可篡改审计服务。

## 结果发布门槛

公开 manifest、任务集、可复核的逐次记录、聚合脚本及实际运行命令；注明未公开材料、环境限制和所有协议偏离。第三方应能重新计算每个分子、分母、中位数和排除项。

在这套评测实际完成前，不宣称“通过率提升至 82.2%”“交付时间降至 31 分钟”“已完成 180 次真实模型评测”“已完成 20 项故障实验”或“全面优于其他 coding agent”。新结果仅描述对应提交、样本和配置，不追溯证明旧数字。
