# 三组真实功能对照协议

本轮功能为现有聊天页面的“导出前遮蔽预览、确认后下载、取消不下载”。它包含独立的数据处理和界面交互工作，不需要服务器部署。此为单个真实功能在隔离副本中的试验，不是生产上线或团队能力排名。

本页记录预先约定的方法；实际出现的维护接续、重复检查和跨组复制偏离见 [执行结果](comparison-results.md)。副本分目录并未形成读取隔离，不能用原计划替代真实执行证据。

## 控制条件

- 模型固定 GPT-5.3-Codex-Spark/low；只有实际额度不足才可更换 5.5，发生切换则单列样本，不直接比较混合模型的成本。
- 三组拥有相同的起始代码、知识正文、固定文案、接口、专业检查清单和独立验收。知识保存进入各自副本，不向后续组传播新经验。
- 顺序在结果产生前确定为 B 固定团队、A 单 Agent、C 动态团队，业务执行不重叠。每组仅一次观察；账户负载、缓存和顺序效应无法由该样本消除。
- B 与 C 均提供两个已就绪工程师槽位。C 可选择 direct 或实际支持的 native/langgraph，并启用零、一或两个工程师。未启用槽位的就绪消耗也单列并计入准备后的总消耗；不能把本次预置资源池试验当成按需创建任务的成本实测。
- A 由唯一开发者使用 direct。B 固定数据逻辑与前端职责，但允许独立工作并行，不强制增加测试或运维会话。三组共享同一套独立验收，由控制器运行。
- 控制器与 Skill 冻结在本轮开始时的版本；测试采集器只读日志。不能为了某一组通过而修改验收或框架、绕过失败、换 runId。

## 验收与过程数据

原有回归为四个测试文件、44 个断言案例。新增数据验收为六个 Node 测试；浏览器验收覆盖八个场景，包括预览遮蔽、HTML 文本安全、移动端宽度、取消/Escape、确认下载、重复打开和异常不回退原文。浏览器使用已安装的 Playwright 1.62.1 与 Edge，无真实聊天或外部服务数据。

记录首轮独立验收、知识保存状态、失败原因、命令尝试、返修、人工介入、重复实现、文件归属和原项目是否变化。工程验收通过、知识保存完成、人工视觉检查及正式发布分别报告。

优先记录两个时间点：PM 正式收到业务合同到首轮验收的耗时，以及该业务轮结束的耗时。就绪/资源准备、工程师执行区间及 PM 等待/收集区间另外报告；等待区间包含工具、模型和调度延迟，不能全部解释成框架开销。

## Token 口径

采集对应任务本地日志中已报告的累计 token_count，不以文本长度或文件大小估算。按累计计数的增量去重，避免把重复快照相加；跨轮统计减去先前累计值。源码见 [usage.mjs](../src/usage.mjs)。

- 分列输入、缓存输入、输出、推理输出；缓存输入属于输入，推理输出属于输出，均不再额外加到总数。
- 汇总所有测试参与者，包括 PM 的规划、派工、等待后的接续、验收汇报，以及工程师实现、自测和失败尝试。
- 就绪与业务轮分别记录；未启用的已准备槽位不能在总账中消失。
- 当前维护任务承担共享准备、采集和观察，模型与测试角色不同；单列维护用量，不随意均摊到某组。生成报告时维护任务仍运行，其用量是截至采集时的部分记录。
- 发现计数重置、缺失、矛盾或未结束轮次时明确标注完整性；不补成零，不将已知部分冒充完整消耗。

这些是日志报告的使用量，不是账单金额或订阅额度。Codex 官方文档介绍了 [App Server](https://learn.chatgpt.com/docs/app-server)；本次具体字段与统计方式依据本机实际日志核对。浏览器接口参考 [Playwright Browser](https://playwright.dev/docs/api/class-browser)，使用运行时随附的 Apache-2.0 许可版本。

## 解释边界

比较的是达到相同验收要求的交付结果与实际代价。未完成的组不能凭较低消耗获得“更省”的结论。只有成功交付且数据完整的样本才讨论单位交付消耗；一次样例的差异不推导总体提速率或稳定错误率。

若动态组最终选择了与固定组相同的任务分配，必须指出两者在本功能上的执行结构相同，不能将随机差异解释成动态调度的结构优势。
