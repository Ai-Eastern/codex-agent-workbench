# 12 题探索性对照协议

协议版本：pilot-12/v1，2026-09-21。规则来源：[DEVELOPMENT.md 第 14 节](../../DEVELOPMENT.md#14-验证与评测)。状态：题目目标、对照口径和记录规则冻结；两个评测仓库、独立验收及运行 manifest 尚未建立。**当前获准付费调用数为 0，已执行对照运行数为 0，没有比较结果。** 本文不是运行授权，也不是可直接启动的评测命令。

本协议将“准备好设计”与“冻结可运行输入”分开。下列 12 题的范围是固定设计，代码、验收和环境哈希不得用占位值冒充已冻结。正式开始前，集成负责人创建两个新的自包含样例仓库、固定各题基线与验收、提交运行 manifest，再取得明确总预算；若修改业务题意或评分口径，发布新协议版本并保留旧版。

## 任务集

两仓库的计划领域为 R1“离线批处理工单服务”和 R2“离线文档 SDK 与检索”；这是待创建评测资产的代号，不是声称已经存在的仓库。每题独立从所登记基线开始，包含修复前/后的回归检查，不能沿用上一题的答案。已有 A/B/C 夹具只用于机制开发，**不计入这 12 题，也不把参考实现算作模型交付**。

| ID | 类别/仓库 | 固定任务目标 | 独立验收与阶段特征 |
| --- | --- | --- | --- |
| P01 | 修复 / R1 | 批量导入遇到坏行仍保存其它有效行 | 空行/缺字段/混合批次返回稳定一基行号与错误码；不改输入；单项短修复。 |
| P02 | 修复 / R2 | 恢复 SDK 旧位置参数调用兼容性 | 新旧调用生成相同请求和结果，保留传输异常与 HTTP 错误；改动不破坏既有调用。 |
| P03 | 修复 / R1 | 重复提交相同幂等键只能产生一次可观察副作用 | 首次、重放、异参同键冲突、失败后重试均有独立断言；不能靠关闭检查通过。 |
| P04 | 修复 / R2 | 同分检索结果顺序与项目范围稳定 | 遍历输入排列，固定分数/ID 排序；同名跨项目资料不得进入结果；保护旧查询接口。 |
| P05 | 功能 / R1 | 增加导入预览，返回与正式执行相同的校验摘要但零写入 | 校验/摘要可独立实现，集成前接口冻结；预览成功和失败都不修改存储。 |
| P06 | 功能 / R2 | 增加可恢复的分页游标 | 固定结果快照中无丢失/重复；非法与跨项目游标被拒绝；页边界和末页行为固定。 |
| P07 | 功能 / R1 | 增加租户导入约束并处理中途需求修订 | 在 v1 校验交付后、持久化阶段开始前触发固定 v2 规则；保存 v1 结果，v2 防串租户；旧结果不能满足新验收。 |
| P08 | 功能 / R2 | 增加限定项目的 JSON 与纯文本导出 | 两种格式实现允许独立工作，共享筛选接口；字段集合、转义、空结果和来源范围固定，最终两格式一致。 |
| P09 | 重构 / R1 | 合并重复字段标准化实现 | 既有与新入口共用规范化，输入不变；输出、错误码和调用签名与冻结回归相同，不新增业务行为。 |
| P10 | 重构 / R2 | 分离请求构造与传输执行 | 新旧 SDK 调用及错误传播完全保留；构造测试不依赖网络；不以新增抽象数量评分。 |
| P11 | 重构 / R1 | 把校验与写入拆为可接续阶段 | 校验产物冻结后在预定位置中断；从真实新上下文保留约束/失败并接续写入；有效校验交付不得重做。 |
| P12 | 重构 / R2 | 将排序和范围过滤收敛到一条公共路径 | 查询/分页/导出回归均保持结果；同分和项目隔离断言；检查明确依赖链与阶段交接，不主张未经实测的性能改善。 |

每题实际材料须附：文字需求、公共接口、非目标、允许写集、依赖、输入样例、可见检查、独立验收、故障/变更触发点（如有）。验收由集成负责人在执行前冻结，生成代理不能修改。不存在独立不可读验收环境时只标功能诊断；同一账号的文件夹或 Skill 边界不能宣称隐藏盲测。

## 两组与公平性

主对照为原型控制器和升级控制器，模型本身不是处理变量。原型源码基线采用开发规范登记的 `8c85c7672f5e289ba7ca72b5d7ea4e6ae9efdd17`；升级组的完整提交在运行 manifest 中冻结，目前尚未指定。两组各 12 题、每题 1 次，共 **24 个预定运行槽位**，均尚未运行。每次用同一题的相同业务基线、需求、可见知识、工具权限、明确模型与推理配置、总资源上限和返修规则；原型可用自身已有原生并行能力，不人为强制串行。

为避免调度顺序完全与方案绑定，奇数题先原型、偶数题先升级，按题号执行并记录实际顺序和偏离。两个方案的可读历史、知识回写与工作区独立；一组不得获得另一组的答案、失败分析或最终代码。无法做到的隔离项必须记录，该组不能用于盲测排名。实时服务版本、系统负载、运行日期与缓存条件是潜在混杂因素；单次配对只支持探索性描述。

先冻结所用宿主/工具/Node/依赖版本和每角色请求模型/推理配置，再登记可观测实际值。实际服务模型无法观察时填写 `null` 并报告缺口，不能用提示词、自述、配置回显或历史记录补齐。模型/权限/预算偏离的运行保留原记录，不能悄悄降级、换模型或删除后重跑。原生 Codex 第三组、消融、重复试验和 360 次扩展均不包含在本协议授权内。

## 启动前预算门槛

默认状态为 `authorizedPaidCalls: 0`、`authorizedRunIds: []`。没有运行预算时只允许源码、确定性测试、资产准备和协议复核；不能因为协议写有 24 个槽位就开始调用。正式 grant 须绑定协议哈希、两控制器提交和具体运行槽位，至少写明：

- 整批最大付费/模型调用数、最大墙钟时间、允许运行槽位及是否允许补跑。
- 每次运行的最大墙钟、每任务尝试/返修次数、同时活跃负责人/执行者容量；子预算从整批预算分配，重试或交接不重置。
- 角色模型与推理配置、允许的宿主操作、实际 token/费用能否观察，以及预算观察缺口。
- 停止规则：完成、用户暂停、时间/调用预算耗尽或权限/证据问题时停止新派工；在途消耗和未知送达保留并对账。

token 数据缺失时不能宣称精确 token 硬上限。付费额度和墙钟等可执行上限先约束派工；实际用量作为事后记录。批准前所有正向预算值保持未定，不以任意样例数字取得默示授权。必要小试只覆盖批准的槽位与假设，不自动补足全矩阵。

## 每次运行的固定记录

记录文件保留本机，公共副本用代号脱敏。正式 manifest 的预算、版本和必需哈希不能为占位；尚未观测的运行值使用 `null` 并列入 `missingObservations`。

| 范围 | 最少字段 |
| --- | --- |
| 协议/题目 | `schemaVersion`、`protocolVersion`、`protocolHash`、`taskId`、`category`、`variant`、`runId`、`repetition: 1`、运行槽位和顺序、`replacementOf`（通常 `null`）。 |
| 可复现输入 | `repositoryId`、`baselineCommit`、`controllerCommit`、宿主与工具版本；需求、可见知识、允许写集、接口、可见检查、独立验收、依赖锁、环境与请求模型配置的内容哈希。 |
| 身份/版本 | 各负责人/执行者身份映射、实际会话和所属项目、计划/任务/attempt 版本、动作 ID、输入包哈希、用户授权及 grant 哈希。 |
| 产物 | 预算结束前最后一次正式提交的 `finalCommit`；没有提交则 `null`；原始 diff/产物哈希、每次验收脚本与结果哈希、事件顺序与日志哈希，失败与未提交状态一并保留。 |
| 模型 | 各角色 `requestedModel`、`requestedReasoning`、`observedModel`、`observedReasoning`、原始可观测来源；未知不填猜测值。 |
| 时间 | 请求进入、设置开始/结束、派工/接收/交接/暂停/恢复、首次正式验收、最终裁定时间；总墙钟、设置、规划、等待、协调、执行、返修的观测依据与缺失项。 |
| 状态 | `not-run`、`running`、`passed`、`failed`、`timeout`、`paused`、`infrastructure-failure`、`budget-exhausted` 或 `capability-unavailable`；失败理由、全部尝试与修复、协议偏离。 |
| 人工 | 每次人工介入/传话/冲突处理的次数、耗时和原因；真实宿主身份创建的设置成本也记录。 |
| 全角色用量 | 根协调、项目/组主、原生执行者，以及规划、交接、恢复、验收、统计报告各角色的输入、缓存输入、输出、推理输出、来源与采样截止时间。 |

输入包含缓存输入，输出包含推理输出，不能重复相加。缓存未知填 `null`，不能当零或通过更換新上下文宣称冷缓存。token 不直接等于订阅费用；仅在确有相应账单/计费依据时单列实际金额。框架建设、一次性注册/安装设置、单次执行/协调和报告成本分账展示，端到端口径写清包含项；不能只展示执行者成本而省略主代理开销。

已完成的三项目真实案例若将来有可用记录，只复用其已存证据做成本归因，不为写报告重跑。它有自己的运行 ID、目标和分母，不能补入这里的 24 个槽位。

## 裁定、分母与发布

首次正式验收通过与返修后最终通过分别计数；达到时间/预算上限前最后一个正式提交是唯一待评分结果，不在多个尝试里挑最优。改写冻结验收、错误项目/版本放行或不可审查交付不算通过。控制器正确拒绝一次注入故障是机制证据，不能单独计为该编码题交付成功。

每组公布预定 12 槽位、实际启动数、未启动数及原因、首次通过、最终通过、失败、超时、暂停、能力缺失和基础设施失败。所有已开始尝试均保留在明细与启动分母中；未开始不算失败，但不能省略以伪装完整试验。结果同时展示“通过 / 已启动”和“通过 / 预定 12”，并明确未完成比例。补跑必须新增授权、独立 ID 和 `replacementOf`；原失败不删除，原槽位结论与补跑后的探索结果分开展示。

主要时间口径包含设置后实际任务进入至最终裁定的规划、等待、协调和返修，设置耗时单列，并另报从设置开始的总时间。超时或预算终止按获批墙钟上限记封顶评分时间并标记删失；外部暂停单列暂停区间，不从观察墙钟中偷偷扣除。成功样本耗时可单列，但必须与全体成功率和失败时间并排，不能仅比较成功样本来宣布提速。

附逐题配对差值、原始计数和缺失项；12 题单次探索不支持总体胜率、可靠因果结论或行业排名。任何性能、成本和返工改善数字均等待真实对照之后计算；当前没有可填的数值。公开结果必须绑定准确提交和运行日期，并提供足以复算分子、分母、耗时与用量的脱敏记录、聚合方法和协议偏离。源码/CI/合成夹具通过不能替代这一步。
