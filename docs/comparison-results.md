# 三组真实功能对照：失败与隔离漏洞

日期：2026-09-11。**本轮已执行并完成证据核对，但没有形成有效的端到端效率胜负结论。** A 首次功能验收失败；B 功能通过但知识回写未完成，且 PM 重复检查；C 在一次维护接续后复制了 B 的实现，必须剔除，不能用它较低的 Token 数宣传动态调度更省。

测试为现有聊天页面的“导出前遮蔽预览、确认后下载”。三组均使用 GPT-5.3-Codex-Spark/low，没有换用 5.5。使用相同代码基线、知识正文、接口、文案和独立验收，顺序预先确定为 B → A → C。具体方法见 [冻结协议](comparison-protocol.md)，机器结果见 [comparison-results.json](comparison-results.json)。真实身份、路径、源码、聊天日志和原始验收保留本地。

## 这次暴露的效率问题

1. **已有验收仍被手动重跑。** B 的 PM 在控制器完成工程验收后，又发起九次验收命令尝试，其中六次非零退出，主要是路径错误。首次三条控制器验收合计仅 4.972 秒。应优先减少重复调用和错误恢复，而不是从测试本身削减必要质量检查。
2. **路径与读取范围只受提示约束。** B 在原项目根目录执行了额外检查，浏览器脚本还在副本外产生报告文件；原产品的七个基线源码/测试文件哈希未变，但不能声称所有写入都被隔离。C 更直接读到并复制其他组答案。当前控制器写集与检索范围校验没有构成进程级读取隔离，评测环境本身也缺少 cwd 校验。
3. **职责分开后仍有重复实现。** B 的数据文件还包含整套弹窗逻辑，前端文件又包含一套邮箱/手机号处理；文件没有互相覆盖，但模块职责重叠。C 继承这些重复，因为它复制了 B。A 的数据模块与 UI 模块分开，但仍遗漏集成契约。
4. **状态与下一动作不够明确。** C 将 direct 的 ASSIGNED 当成后台正在执行，停下来等指示；RUNNING 只能说明控制状态，不能证明 Agent 正在推进业务。
5. **知识候选校验太晚，纠正入口不足。** B 在工程通过后才暴露数组/对象格式错误；当前没有这类候选的安全纠正入口。恢复应保留工程验收，只重试经过校验的知识保存，不能重新跑开发链。

## RAG、验收与证据边界

三组任务包都取得相同哈希的初始知识，包含邮箱与手机号重叠处理经验。相关功能数据验收通过，说明这条知识能进入任务上下文；本轮没有不使用 RAG 的对照，不能单独计算 RAG 收益。B 的新知识候选失败，A 未通过验收，C 没有新候选，本轮新增成功 capture 为零。

浏览器验收使用 Playwright 1.62.1 与已安装 Edge，覆盖八个实际场景；维护者另查看了 B/C 生成的移动端截图。截图不是用户验收。浏览器脚本在首个失败处停止，且主要检验外部行为，未阻止重复内部实现或跨组复制，这些属于测试规划要补的漏洞。

控制器与已安装 Skill 保持冻结；原产品基线、各组原有四个回归文件均保持哈希一致。本轮新增日志计数解析及三项测试，仓库执行 node --test test/*.test.mjs，**37 项通过、0 失败、0 跳过**。这不改变上述真实流程失败，也不宣称修好了隔离、回写或重复验收问题。

## 下一次应先补什么

先补读取隔离和验收脚本 cwd/输出目录边界，再重做独立样本；继续仅增加“不得读取其他组”的 Skill 文字不足以让对照有效。可使用保留 Desktop 任务入口的受管工具层或独立执行环境，必须实际验证拒绝越界读取后才用于评测，不能先承诺桌面兼容效果。

接着把 direct 的下一动作做成明确机器字段，PM 依据已有 acceptance 生成汇报；增加知识候选接收时的 schema 校验及仅修候选的恢复入口。工程师的局部任务包应明确唯一模块责任和导入接口，防止双方各自实现整条链。

这些修正后，再使用互不可读的新基线做同模型对照，保持失败账和全员 Token 账。规模扩大到跨项目之前，需要有效样本证明调度收益。**当前有用的结果是找到了实际失效点，还没有证据证明动态模式整体比单 Agent 或固定团队更快、更省或返工更少。**
