# 阶段交接与收尾改造

本次把上一轮成本观察中的三个改进点落实到现有 Workbench，没有安装新编排组件或更换模型。

1. **短阶段交接。** 新阶段接收目标、明确配置、上一阶段 `delivery` 和必要代码入口，项目知识按当前任务检索。它不携带完整聊天。对有明确创建授权的阶段接续，在同一桌面项目下启用新 PM；旧任务、旧配置和证据保留。未调用原任务 compact 或修改 Codex 状态库。
2. **一轮选题与派工。** 总经理在一个已授权轮次内核对目标并创建/绑定阶段 PM，创建消息就是完整开发委托，没有第二条“开始”或单独就绪轮。本次交接提示为 1,441 字符。
3. **工具生成收尾。** `delivery --project --run [--output]` 从现有控制器证据生成事实包；完成的 `continue --output` 直接保存同一对象。拒绝未完成、暂停、漂移的验收/产物/回执，不执行新的验收或捕获。输出文件独占创建，避免为了保存回执覆盖旧证据。

## 身份和历史

已核对 `projectIdentity` 包含 PM ID，因此使用新阶段配置文件。旧配置字节未变；新旧配置只改变 PM ID，保持相同工作目录、controlRoot、知识库和工程师上限。登记表及项目 AGENTS 当前入口指向新配置，历史运行继续使用旧配置。旧文件锁没有被新控制库绕过。

新 PM 位于原“恋语”保存项目下，模型 Sol/high；总经理仍为 Astra/ultra。工程师配置仍为 Luna/medium，是否使用工程师由任务依赖决定。新的真实任务是已有 6+6 数据包的显式参数 CLI，采用 direct，不人为安排并发。

## 验证范围

新增功能相关测试覆盖完成事实复用、未完成/暂停/产物与知识漂移拒绝、CLI 输出可再次 JSON 解析、拒绝覆盖、已结束 continue 的验收/知识回执不变，以及关闭捕获时明确报告边界。全仓 106 项：105 通过、1 个 Windows symlink 环境跳过、0 失败。已安装 Skill 与源码一致，UTF-8 校验通过。

上一阶段真实数据交付已通过新 `delivery` 入口读取，验收和知识回执哈希与原记录一致；没有为生成交接再次运行该业务验收。当前真实 CLI 开发的交付结果和成本单独记录，不能把不同任务的观察差异解释为严格因果提效比例。
