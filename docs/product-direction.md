# 产品方向：从真实编码任务到可评审补丁

产品定位是 **面向有界仓库改动的本地 coding agent 工作台**。开发者使用现有 Codex CLI 编码，工作台负责任务约定、Git 工作区、固定验收、失败修复和交付记录。首次体验直接操作仓库中的任务，技术展示服务于这条主流程。

## 当前主流程

选择已有提交的 Git 仓库和仓库外状态目录，填写目标、精确写集与验收命令。工作台创建 detached worktree 并调用真实 Codex CLI；控制器随后检查文件范围与保护文件哈希，再运行验收。失败保留，明确原因后使用一次修复预算；通过后提供实际 diff，由用户评审。

浏览器入口是 npm start，CLI 入口是 npm run agent。两者共用 src/local-runner.mjs，没有另造一套业务状态。初次用户也可以用 npm run smoke:agent 创建独立小仓库，实际调用 Codex 完成一次任务；命令明确消耗真实额度。

npm run demo 保留为次级只读机制检查，采用公开固定补丁、零模型调用。它不替代主工作台，也不作为真实编码成绩。

## 竞争力落点

主流工具已有子 Agent、工具执行、会话接续与工作区能力：[Claude Code](https://code.claude.com/docs/en/overview)、[OpenCode](https://opencode.ai/docs/)、[OpenHands](https://docs.openhands.dev/overview/introduction)。这些资料用于理解产品边界，不构成同条件性能比较。

本项目围绕具体价值积累证据：**这次改动为什么可以交付、失败后如何处理、哪些后续变化会使旧结论失效。**

| 用户问题 | 当前产品行为 |
|---|---|
| Agent 在哪里修改？ | 从确定提交创建独立 worktree；交付检查使用明确文件清单。 |
| “做完了”的依据是什么？ | CLI 执行完成后，控制器另行运行预定验收命令，再形成补丁与回执。 |
| 失败会不会被自动重试掩盖？ | 保留原失败，记录修复原因和新 attempt，限制修复预算。 |
| 已通过的结果是否仍有效？ | 查询交付时重新检查绑定产物、patch 与 HEAD；漂移显示 EVIDENCE_CHANGED。 |
| 能拿走什么？ | 可查看、下载的实际 diff；工作台不自动合并。 |

这些是可检查的产品行为，不宣称市场独有、全面领先或必然提升生产率。

## 已到达的验证边界

2026-09-21 已完成一次真实 Codex CLI 小任务：规范化标签实现被实际修改，固定 Node 测试的两条断言通过，得到 READY_FOR_REVIEW 与补丁，原仓库保持不变。该调用沿用本机模型配置，服务端模型身份未观测。完整自动测试为 204 项、203 通过、1 跳过、0 失败；测试大多使用假进程或注入执行器，不能与一次真实调用混为模型样本集。详情见 [验证记录](verification-20260921.md)。

一次烟雾测试不证明复杂项目交付能力或提速。下一步优先记录实际用户任务中的阻塞、返工和评审过程，再决定扩大任务规模。

## 当前产品范围

- 每个本地任务一个编码执行者，使用 direct 合同，复用 LangGraph/SQLite 持久控制器。
- 非交互 Codex CLI、stdin 提示词、原始 JSONL/stderr/最终消息；不替用户登录或擅自选模型。
- 精确写集、验收文件哈希、Git worktree 与基于临时 index 的补丁导出。
- 指定 Markdown 检索与上下文冻结；本地入口未开启验收后自动知识回写。
- 单机浏览器服务与终端入口，页面观察近期事件，磁盘保存进一步核对所需记录。

既有 Desktop native / LangGraph 路线仍在仓库中，新网页尚没有多角色依赖图并行或端口租约。新增路径也不包含隐藏测试保密、独立容器验收或额外 OS 访问隔离。原仓库 HEAD 漂移会被检测，任务期间未提交内容变化尚未全量检测。

## 接下来按真实使用推进

| 工作 | 达成条件 |
|---|---|
| 扩展真实任务样本 | 经授权在更多小型实际项目完成编码与验收，保留所有失败和中断；不把单次成功改写成成功率。 |
| 降低安装与项目准备成本 | 外部使用者能按 README 配置路径、依赖和验收，理解 worktree 不含未提交内容与被忽略的本地依赖。 |
| 完善恢复 | 根据真实中断处理残留锁、执行进程与状态的一致性，不用重新调用模型冒充恢复。 |
| 发布模型评测 | 按 [评测协议](evaluation-protocol.md) 固定任务和预算，先验证验收隔离条件，再发布完整样本与可重算统计。 |
| 验证产品价值 | 记录评审者是否更容易理解改动、定位失败和完成交付，用实际结果决定功能取舍。 |

不以截图、机制断言数、窗口数量或代码量替代真实交付效果。本次复用现有控制器、知识模块和 Node 标准库，没有新增前端框架或模型编排依赖。
