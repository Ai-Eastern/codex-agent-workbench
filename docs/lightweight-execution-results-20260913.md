# 普通执行入口简化

已实现并同步桌面 Skill：普通任务由 PM 直接实施或按需使用原生子 Agent；总经理按项目目标、里程碑和异常协调。现有桌面项目、角色配置、Obsidian 知识、失败记录与文件归属保留。

| 场景 | 之前 PM 的必要控制器命令 | 现在 |
|---|---|---|
| direct | prepare → start → submit → continue：4 次 | begin → finish：2 次 |
| native，3 个子任务、身份齐备 | prepare/start、3 claim、3 bind、continue：9 次 | begin、批量 bind、continue：3 次 |
| native，创建后立即逐个绑定 | 同上：9 次 | begin、3 bind、continue：5 次 |

上表只计算 PM 的 CLI 操作，不包括检索、写合同、原生创建/等待、工程师各自 submit、自测或异常恢复，也不等于模型轮数或 Token 节省。原生子 Agent 仍由 PM 调用真实工具创建，CLI 不会创建或猜测身份。只返回协调名称时仍须向子 Agent 核对 UUID。

## 实现和边界

- `begin` 复用 prepare/advance，native 整批领取后返回创建包。重复调用只读取匹配合同的状态；暂停、失败或已完成不会重新领取、派工或验收。桌面模式继续使用原入口。
- `bind --bindings` 在同一 SQLite 事务绑定多项真实身份；任何一项不合法全部回退。单项形式保留，两种形式均要求 PM 身份、运行中且未暂停。没有独立创建回执，UUID 格式通过也不能当作真实创建证明。
- `finish` 只用于 direct PM，复用 submit、正式验收及证据绑定的知识保存。结果已写但后续操作失败时保留结果，沿原状态/continue 接续，不覆盖结果或重复执行 finish。
- direct 的执行提示保留当前 PM 模型，不将工程师模型配置当成 PM 的换模要求；native/桌面包仍携带明确工程师模型与推理档位。
- 知识候选严格拒绝非法字段，报错给出字段名和允许字段，说明 source 由控制器绑定；不打印字段值或知识正文。有效结果和引用按产物版本复用，正式集成验收仍保留。
- 内部继续使用既有 LangGraph 与 SQLite，没有实现新的跨项目后台调度器或更换状态库。跨项目独立工作不需要统一开工屏障；显式同步桌面批次保留原机制。

## 验证

全套测试 **155 项：154 通过、0 失败、1 项既有平台跳过**，耗时 3,760.0142 ms。新增 10 项合并入口测试，覆盖来源绑定知识保存、模拟子任务身份校验、整批绑定回退、重复调用、文件冲突、输出保护、失败保持、compact 创建包与提交后中断恢复；另更新非法字段报错回归。

独立只读审查发现“领取后暂停仍返回 CREATE_NATIVE”的竞态。先用注入暂停复现失败，再改为检查最新状态、任务和 attempt；回归现已通过。全套首次执行发现旧计时测试未设置新增绑定要求的 PM 身份，补齐该测试前提后通过。旧角色提示断言也按 direct PM 沿用模型的行为修正；没有放宽权限或取消检查。

仓库和安装目录的 Skill 校验均通过；五份更新材料合计由 9,106 降至 6,502 个 Unicode 字符，按 CRLF 统一后计数，不等于 Token。Windows Python 默认 GBK 导致初次读取中文失败，使用 `-X utf8` 后验证成功；Skill 原文保持 UTF-8。新版保留知识候选禁止 source 的既有规则，并修正 direct finish 与工程师 submit 的角色区分。

这些是本地功能与边界测试，未启动新的产品任务或真实三项目并发批次。没有宣称本次改动已经降低完整交付耗时、Token 或错误率。原始测试输出和安装前备份仅保留在本机 `.local`。复用决策见 [记录](lightweight-execution-reuse-20260913.md)，源文件哈希和验证汇总见 [数据](lightweight-execution-results-20260913.json)。
