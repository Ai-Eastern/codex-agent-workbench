## 真实桌面功能验证：保留两类失败

两个任务均新建于现有项目，使用原有 Desktop 侧栏入口，没有更换操作方式。

**Direct 首轮不是无辅助成功。** 尽管委托给出了唯一配置，PM 仍先使用上层默认配置，在那里产生一条错误运行与两个 work 文件；随后才转入指定测试副本。这暴露了请求没有绑定项目身份的缺口。没有回滚或删除错误记录；随后补入新请求的 projectId 硬匹配，未追写已冻结请求。

正确副本的首轮正式验收也失败，但原因属于维护者：生成的检查脚本字符串包含真实换行，Node 在解析阶段抛出 SyntaxError，尚未执行任何断言。维护者归档原检查脚本、原 freeze、原失败 acceptance，再修复脚本语法并先执行静态语法检查，同时让上下文检查先于实现模块导入。原四项行为断言、请求及两份交付文件未变。该修正单独记录为测试脚本修订，不能把原始冻结版本说成通过。

随后只登记一次明确的验收接续。原 PM 使用同一个 runId 执行一次 continue，四项断言通过，状态为 COMPLETE，保存一条知识；成功检查输出计数为一次，原失败哈希及归档字节仍一致。没有再次实现代码，也没有把失败隐藏为新样本。

**新会话知识检索通过。** 第二个 5.5 Desktop 任务只收到明确配置和问题，从 search 命中本轮新捕获经验及种子笔记；核对知识、acceptance 和两个关联产物的 SHA-256，并正确说明本地命令证据的适用范围。它没有重新开发、派工或执行验收，也没有读取旧任务聊天和其他组实现。检索前仍有两次不支持的 CLI 帮助调用，已计入真实消耗；这次访问过全局记忆登记摘要，因此仅证明新会话检索闭环，不称为完全无历史资料的盲测。

## Windows 读取隔离：有效的部分和未接通的部分

核对本机 CLI 0.153.4 的实验协议 schema、当前 Desktop 工具入口及官方 [Permissions](https://learn.chatgpt.com/docs/permissions) / [App Server](https://learn.chatgpt.com/docs/app-server) 文档后，做了确定性命令探针；这些探针没有启动模型推理轮次。

| 探针 | 观察结果 | 可得结论 |
| --- | --- | --- |
| 初次 CLI sandbox，root deny 配置 | A 与 B 都可读，子进程退出码 9 | 隔离失败，原记录保留；不能因为外层采集器正常退出就判通过 |
| 独立 App Server 启动临时 thread | 返回 activePermissionProfile | 只证明配置选择，不证明文件读取已受限 |
| App Server command/exec，root read 加明确 B deny | A 可读；B 返回 EPERM；子进程退出码 0 | 当前 Windows 受管命令确实执行了指定路径拒读 |

成功探针采用根目录可读加局部拒读，**不是完整文件系统白名单**。未实测的路径、网络、连接器或工具面不能由这两个哨兵文件推断。

当前 Desktop adapter 的 read_thread / send_message_to_thread 入口没有 permissions/cwd 配置和 activePermissionProfile 回读面，无法把受管命令权限直接覆盖现有侧栏任务的全部工具。独立 App Server 的权限响应不等于 Desktop 后续轮次沿用同一权限；不能用双运行时同时接管一个任务来弥补证据。

因此本轮没有改变全局 Codex 权限、重启 Desktop 或声称操作系统隔离已部署。后续接入要先解决：**由 Desktop 任务入口可靠绑定执行权限、回读实际生效配置，并验证常用工具与绕过路径均不能读到其他组答案。** 保留侧栏是硬要求；满足这个条件前不启动新的效率排名。
